# Gitpal — Infinity AI Builder and Asset Harvest

Gitpal is the guided entrance for advanced website builders, creators, researchers, and users who want to turn a short idea into a working Infinity product without digging through raw GitHub complexity.

Gitpal does not treat GitHub as a pile of files. It scans repositories, identifies useful components, explains what is working or broken, and guides the user through importing, repairing, combining, testing, and publishing approved assets.

## Core flow

```text
User query or project seed
        ↓
Encrypted Infinity workspace
        ↓
Gitpal scans approved repositories and components
        ↓
AI creates a build plan and C13b0 action tree
        ↓
Gitflow organizes the work sequence
GitPin anchors source files and provenance
Gitpro applies visual and product rules
Gitarch checks structure
Gitpulse checks health and errors
Gitscan inspects dependencies and risk
Gitsync reconciles approved versions
Gitpub prepares publication
        ↓
Working website, game, app, research product, or asset package
        ↓
Verified build record and harvest event
        ↓
Wallet receives the awarded asset or settlement record
```

## Privacy and encryption

User queries, private source links, unpublished designs, prompts, research, wallet information, access tokens, and generated knowledge must be encrypted at rest with authenticated encryption. Encryption keys must stay outside GitHub and outside browser source code.

Public repository metadata can remain readable. Private user content must be stored separately from public code and decrypted only for an authenticated Infinity user or authorized Infinity AI service.

## Action and token model

Every meaningful event can be recorded as an action:

- Query submitted
- Repository scanned
- File inspected
- Component imported
- Dependency checked
- Design selected
- Code generated
- Test executed
- Error repaired
- Version saved
- Asset packaged
- Product published
- Approved user interaction recorded
- Sale, license, or award verified

A large AI build may create hundreds of internal action records, but those records do not automatically become spendable currency. The user-facing reward follows the active Infinity policy, daily limits, funding source, verification rules, and authoritative ledger.

## Asset ownership and provenance

A generated site or product may involve several separate rights:

- The user's originating query and creative contribution
- AI-assisted construction work
- Imported open-source components and their licenses
- Original Infinity design systems and tools
- A publisher, studio, merchant, or customer license
- The final deployable product
- The collectible build record or token

Gitpal must never imply that a query automatically transfers every copyright or ownership right. Instead, it creates a signed provenance manifest that states who contributed what, which licenses apply, who controls the deployed product, and which awarded or tradeable asset belongs in each wallet.

## Harvest feed

The Harvest Feed shows verified creation events rather than random Bitcoin values.

Examples:

```text
King Website build completed
→ tests passed
→ provenance manifest signed
→ asset package issued
→ harvest event recorded
```

```text
Research article personalized
→ source checks passed
→ contribution approved
→ Infinity subunit settlement recorded
```

```text
Licensed website sold
→ payment verified
→ creator, publisher, platform, and rights-holder allocations recorded
→ wallet assets updated
```

Real Bitcoin appears only when an actual Bitcoin transaction, Lightning payment, mining payout, donation, or authorized revenue source is verified. GitHub activity and user clicks can create action records and product value, but they do not create Bitcoin by themselves.

## First working application

The first Gitpal interface should include:

1. A simple project or five-word seed input.
2. An encrypted private workspace indicator.
3. Repository and component discovery.
4. A plain-language AI build plan.
5. A visible action tree with status and provenance.
6. One-click preview imports that do not write to GitHub.
7. Explicit confirmation for stars, forks, commits, pushes, and publication.
8. Automated browser tests and a repair report.
9. Export to StarQuest, Alien Coin, Alien Radio, Bitcoin Crusher, Infinity Graphics, 3D World, or Image Generator.
10. A Harvest Feed entry only after a verifiable milestone.

## Security boundaries

- No secrets in the repository.
- No private vault key in client JavaScript.
- No arbitrary remote script execution.
- Imported code runs in a restricted preview environment first.
- Dependency and license checks occur before publication.
- GitHub writes require explicit user approval.
- Wallet issuance requires signed server events.
- Copied asset metadata does not transfer ownership.
- Recovery, revocation, and key rotation are required.
